## 🎯 the grainmirror pattern

each repo maintains TWO readme versions:

1. **`readme.md`** - live version (github displays this)
2. **`{grainorder}-{timestamp}--readme-{org}-{repo}.md`** - grainmirrored snapshot

**why?**
- github still displays `readme.md` normally
- snapshots track version history
- hub repos can show ALL readmes from ALL teams chronologically
- filename pattern makes it obvious which repo each came from!

**example:**
```
teamshine05/graintime/
├── readme.md  (live, github shows this)
└── xzvskk-...-readme-teamshine05-graintime.md  (grainmirrored)

teamkae3gtravel12/ (hub)
├── readme.md  (its own live readme)
├── xzvskk-...-readme-teamshine05-graintime.md  (mirrored from teamshine05)
└── xzvskg-...-readme-kae3g-teamkae3gtravel12.md  (snapshot of its own readme)
```

## 💭 philosophy

### grainorder: newest = smallest

github sorts a→z (ascending), so:
- smallest alphabetical codes appear at TOP
- newest files get smallest grainorders
- archives use `zxvsnm` prefix to sink to bottom

### graintime: immutable astronomy

git branches encode:
- exact moment (holocene era timestamps)
- moon's nakshatra (vedic lunar mansion)
- ascendant (rising sign + degree)
- sun's house (time of day)

### grainmirror: conscious duplication

instead of symlinks (which github doesn't follow):
- hard copies in multiple repos
- tracked mapping of source → mirrors
- sync on demand
- unique filenames prevent confusion
